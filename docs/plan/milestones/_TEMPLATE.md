## Objective and scope

Describe the observable user outcome, prerequisites, included behavior, and explicit non-goals.

## Decisions and contracts

Record confirmed choices, open questions, API/data changes, permission boundaries, units/timezones, and compatibility requirements. Resolve decisions that block implementation before assigning dependent work.

## Tasks

For each bounded task include:

- Task ID, deliverable, dependencies, and file ownership.
- Acceptance criteria stated as observable behavior.
- Relevant tests and exact verification commands once available.
- Reviewer checklist for correctness, scope, and integration.
- Deployment/data implications and recovery steps when applicable.

## Milestone acceptance

Define automated checks, container validation where relevant, and a concise manual walkthrough with expected results. Separate local validation from external deployment acceptance. Link bilingual reports when produced; never mark unperformed checks as passed.
