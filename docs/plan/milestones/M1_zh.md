# M1 · 日常 Dashboard 与完整历史浏览

> [English — 唯一权威来源](M1.md) · **中文**

本文是实现设计，不是实现报告，也不授权执行。进度由[路线图](../roadmap_zh.md)管理。人工开发者和编排执行者均可使用本文；本文不分配模型。明确授权实现后，遵循 [agent 指引](../../../AGENTS_zh.md)。

## 1. 目标与范围

将现有数据验证界面升级为适合手机、平板和桌面的紧凑、信息充分的日常 Dashboard，逐步替代 TeslaMate Grafana。M0 和 Alpha 后安全/PWA 工作是已有基础，不重复建设。

### 已确认的产品范围

- 精简概览，结合最近已知车辆数据、期间摘要和最近记录。
- 全局选择单辆车，跨页面保留车辆上下文。单车实例弱化选择器。M1 不做跨车汇总。
- 通过日期选择器访问完整历史，包括跨年和全部历史，替代 UTC 文本输入。
- 完整常用行程、充电流程，提供有用的列表摘要、详情、曲线和返回状态恢复。
- 基础指标、估算行驶能耗和已有充电费用。
- 行程速度、功率、电量、温度、海拔曲线；充电功率、电量和室外温度曲线。
- 紧凑现代布局、响应式导航、浅色/深色外观。
- PostgreSQL 历史及最近记录，不做持续 MQTT 接入。

完整产品围绕概览、行程、充电、分析、足迹组织。M1 主导航只展示概览、行程、充电，不为后续功能展示占位页面。

### 非目标

高级统计、电池健康、停车耗电、足迹分析、多次驾驶组成的旅程汇总、统一活动时间线、跨车聚合、导出、充电费用或地点编辑、AC/DC 筛选、通知规则、实时 MQTT、车辆控制、PWA 重建、离线车辆浏览和滚动性能优化均不在范围内。不得修改 TeslaMate 数据、表结构或索引、Linux Install Helper 或任何现有生产服务。

本里程碑本身不授权访问 VPS、真实 PostgreSQL、家庭 MQTT 或真实 SMTP；发布和生产部署属于独立操作。开发和测试仅使用隔离合成服务。

### 基线与规格选择

实现基线为 `v0.1.0-alpha.2`，源提交 `646fdf82d2fdde7a46d7199e51b8bd01be8d926a`。实现前重新检查工作区，保留之后的改动。不假定之前的走查容器、卷、网络和本地 MateScope 镜像仍存在。

上游研究固定为 TeslaMate `c187d0269a31bcaa1497678469e3836ef9a260da`：[dashboard 定义](https://github.com/teslamate-org/teslamate/tree/c187d0269a31bcaa1497678469e3836ef9a260da/grafana/dashboards)。MateScope 当前的“行程”对应上游单次 Drive；上游 Trip 汇总一段时间内的多次驾驶和充电，仍不属于 M1。上游查询用于理解字段，不能不调整权限、边界和缺失数据规则就直接复制 SQL。

下文默认值，例如每页 50 条、rated 续航、600 个曲线桶和布局断点，属于设计选择，不表示用户逐项确认过或生产行为已获验证。它们是本计划的实现默认值；之后若修改，必须在依赖工作开始前同步更新英中版本。运行时币种刻意保留为未设置，等待所有者选择。生产结构兼容性、原生设备验收和部署结果仍未验证；任何任务不得提前描述为通过。

## 2. 页面与使用流程

### 应用框架与共享上下文

| 项目 | 必需行为 |
| --- | --- |
| 主导航 | 概览、行程、充电 |
| 手机，小于 768px | 顶部车辆选择和设置；底部三项导航，尊重安全区域 |
| 平板，768–1199px | 侧边导航及共享车辆/页面上下文；按可用宽度调整内容列数 |
| 桌面，1200px 及以上 | 侧边导航；更宽的摘要、列表及两列详情区域 |
| 设置 | 保留连接、密码、2FA、onboarding 和退出行为；增加展示偏好 |
| 车辆选择 | 显式 URL 优先；否则沿用内存中的当前选择，再否则使用可用车辆中的最小 ID |
| 空/无效选择 | 无车辆时显示空状态和设置链接；URL 选择的车辆不可用时明确提示选择，不静默显示另一辆车 |
| 外观 | 默认跟随系统，可覆盖为浅色/深色；Web Storage 仅允许存储非敏感 UI 偏好 |
| 既有路由 | 保持 `/vehicles`、`/trips/:id` 和 `/charges/:id` 可用；`/vehicles` 不作为主导航项 |

使用现有 React/Mantine 技术栈。增加与已安装 Mantine 8 版本一致的 `@mantine/dates`，不为日期选择升级整个 UI 框架。曲线使用 Recharts。仅在引入其用途的步骤中添加并固定兼容依赖，不增加另一套图表库。[Mantine 8 日期选择器](https://v8.mantine.dev/dates/date-picker-input/)、[Recharts](https://recharts.github.io/en-US/api/LineChart/)。

车辆记录、名称、地点、摘要和曲线仅保存在在线内存中。URL 可包含车辆/记录 ID、已解析时间边界和分页上下文，不含记录内容或地点名称。直接进入详情时，即使此前选过其他车辆，框架也必须显示该记录所属车辆。

### 概览

严格包含三个内容区域：

1. **最近记录值：**电量、所选口径续航、里程表，以及各自的源时间戳。
2. **所选期间摘要：**驾驶距离、估算行驶能耗、充入电量、已记录充电费用。手机两列，桌面最多四列。
3. **期间最近记录：**最近三次行程、三次充电，每个区域链接到完整列表。

最近记录值独立于日期筛选；其余两个区域使用所选期间。标题明确区分。不得添加概览趋势图、仪表、状态时间线或充电状态面板。

距离/估算能耗链接进入行程；充入电量/费用链接进入充电，保留车辆和期间。记录链接进入详情。单个区域失败不隐藏正常区域。区分空结果、缺失值、权限不足和请求失败。重新读取成功不得将旧源样本标为新鲜或“实时”。

### 日期选择

使用日历范围选择器：手机弹窗，宽屏浮层。提供今天、最近 7 天、最近 30 天、本月、今年、全部历史、自定义。允许年/月导航，选择旧日期不需要逐月连续点击。

默认最近 30 个本地自然日，包括今天。按照已保存的 IANA 时区解释日期，不使用浏览器时区；日历以星期一为一周起点。自定义结束日期包含当日。后端转换为 UTC `[start, end)`，今天截止解析时刻。拒绝颠倒范围、不完整的自定义选择和未来日期。跨夏令时分别计算每个日历边界，不累加固定 24 小时。

仅点击“应用”后改变查询；“取消”保留当前查询。移除 UTC ISO 文本输入要求。切车或应用新范围时重置分页。跨页面使用同一已解析范围，直到显式修改或刷新；浏览器返回不得静默解析不同的“现在”。

全部历史从所选车辆最早的行程或充电开始时间起，至解析时刻结束。没有历史时返回明确的空时间窗口，不虚构 1970 等年份，也不发起零宽度列表查询。切换车辆时，为新车辆重新解析“全部历史”预设。

### 行程列表

按本地开始日期分组，按开始时间和 ID 倒序。展示开始时间、起点 → 终点、距离、时长、起止电量、估算能耗。桌面可额外显示估算平均能耗；手机布局不得要求横向滚动。列表截断过长地点名称，详情完整展示。

期间摘要展示整个选定范围的次数、距离、时长、估算能耗，不能只统计可见页。每页 50 条，使用上一页/下一页，不做无限滚动。不纳入地点搜索和高级筛选。没有结束时间的记录仍可见，标为“记录未结束”，不能声称正在驾驶。

### 行程详情

顺序：返回入口及日期/地点；距离/时长/电量/估算能耗摘要；路线地图；速度/功率图；电量图；默认收起的“更多数据”，含车内外温度和海拔。

手机纵向排列；桌面摘要与地图并排，宽度允许时之后的图表区域采用两列。速度、功率分别具有明确单位轴。电量、温度、海拔不得塞入同一张多轴图。地图/单张图失败局限于本区域。复用现有轨迹保护。不做刷选、地图与图表联动、胎压或 GPX 导出。

### 充电列表与详情

列表显示时间、地点、起止电量、充入电量、时长、已记录费用。期间摘要显示次数、充入电量、时长、已记录费用。分组、分页和恢复与行程一致。

详情顺序：地点/时间/摘要；电量变化、充入电量、记录用电量、费用；功率/电量图；默认收起的“更多数据”，含室外温度。不推断缺失用电量，不增加充电效率估算、站点统计或费用编辑。

### 导航、隐私与失败行为

- 从详情返回时恢复车辆、期间、页码、滚动位置和触发记录的键盘焦点。浏览器前进/后退一致。刷新后恢复筛选/页码，不要求精确滚动像素。
- 路由/上下文仅保存 ID 和导航元数据。退出、离线时清理记录缓存。切车时不得继续保留旧车内容。
- 新查询键必须纳入现有离线门禁：时间窗口、摘要、最近记录值、曲线，以及已有列表/详情/地图。取消过期请求；迟到响应不得重新发布旧车、旧范围或离线数据。
- 恢复连接后重新读取。清理历史数据不得引起认证或恢复码流程的挂载/卸载。
- 保留 PWA 安装、Service Worker 更新行为及禁止缓存车辆/API/地图数据的规则。这是扩展已有隐私边界，不是新 PWA 项目。

## 3. 数据契约与指标定义

### API

保留 `/api/v1`、既有路由和字段，以及受认证保护的 `no-store` 响应。在既有摘要中增加可空字段。增加用途明确的接口，不构造一个大型 Dashboard 响应。API 与生成的 TypeScript 类型在各自所属步骤中同步交付。

| 接口，相对于 `/api/v1` | 契约 |
| --- | --- |
| `GET /vehicles/{id}/history-window` | 预设或自定义本地日期；返回保存的时区、已解析 UTC 边界及明确空窗口状态 |
| `GET /vehicles/{id}/snapshot` | 电量、所选口径续航和里程表，每项保留独立源时间戳 |
| `GET /vehicles/{id}/trip-summary` | UTC 边界内的期间聚合及指标覆盖计数 |
| `GET /vehicles/{id}/charge-summary` | UTC 边界内聚合、费用币种/覆盖及不可用数据标识 |
| 既有行程列表/详情 | 增加地点名、起止电量、估算能耗和估算平均能耗 |
| 既有充电列表/详情 | 增加地点、电量变化、用电量和费用 |
| `GET /trips/{id}/series` | 速度、功率、电量、车内外温度、海拔 |
| `GET /charges/{id}/series` | 功率、电量、室外温度 |
| `GET /history/capabilities` | 新增能力组的可用性及缺权限/结构不兼容原因 |

新增摘要要求单辆车。既有列表 API 不指定车辆时的行为保持兼容，但 M1 UI 不提供全车聚合。不存在的车辆/记录返回未找到；无效范围/游标返回校验错误；数据库失败返回已分类的数据源错误。不得替换为 fixture 数据。新增字段/曲线不可用时携带明确能力信息，不返回无法区分的“无记录”。基础安全检查失败仍拒绝数据源。

### 时间与数据库工作量

行程/充电完整归入其开始时间所在期间：`start >= window.start AND start < window.end`。不拆分跨午夜时长或能量。移除 90 天上限，保留严格的时间顺序/游标校验。按开始时间和 ID 倒序分页；游标绑定记录类型、车辆和已解析窗口。

全部历史仍分页。聚合在 SQL 中使用行程/充电过程汇总和必要车辆元数据完成，不下载全部页面，也不扫描所有轨迹样本。保留只读事务、现有连接上限和 5 秒 SQL 超时。超时是错误，绝不是成功的截断摘要。不创建 TeslaMate 索引、汇总表或后台预计算。

### 指标

| 指标 | 定义 |
| --- | --- |
| 次数 | 返回范围内总数、已结束数和未结束数 |
| 距离/时长总量 | 仅累计已结束记录中的有效非负值 |
| 起止 SOC | 原始关联百分比；缺失保持 null |
| 估算行程能耗 | `(开始续航 - 结束续航) × cars.efficiency`，单位 kWh |
| 估算平均能耗 | 有效估算能耗之和 / 完全相同记录的距离之和，转换为 Wh/km |
| 充入电量 | `charge_energy_added`；不得替换为充电用电量 |
| 记录用电量 | `charge_energy_used`；不得用充入电量填补 null |
| 费用 | 已有 `cost`；区分 null 与明确为零 |

能耗采用上游续航差/效率系数方法，始终标记为估算。[固定版本的上游行程查询](https://github.com/teslamate-org/teslamate/blob/c187d0269a31bcaa1497678469e3836ef9a260da/grafana/dashboards/drives.json)。

- 增加 `rated`/`ideal` 续航偏好，默认 `rated`。明确标记口径，在续航与能耗中一致使用；不静默回退到另一口径。
- 能耗要求记录已结束、距离和效率系数为正，输入存在且有限。负续航差令该次能耗不可用，其距离也排除在平均能耗分母外。零续航差是有效零能耗。
- 充电期间电量/时长/费用聚合也仅采用已结束记录。单次未结束详情可显示已记录值，但必须明确为暂定。未结束计数与覆盖情况一并提供。
- 每项聚合返回有效/适用计数。适用记录是该指标的已结束记录；缺失/无效值降低有效覆盖。空期间返回零计数/总量。存在记录但没有合格记录或所需值全部缺失时，返回 null 及原因/覆盖情况，不返回误导的零。未定义平均值，包括零分母，返回 null。
- 后端聚合保留数值精度，仅展示时舍入。不得对每次行程的平均值再取平均。次数为整数；距离/能量/平均能耗最多一位小数，SOC 为整数百分比，记录费用两位小数。
- 单位为 km、km/h、kW、kWh、Wh/km、°C 和 m。M1 不做英制切换。

### 币种

TeslaMate 费用值没有逐条币种。增加可空的展示币种偏好，不从语言/时区推断。未设置时，单次费用显示原始值及“币种未设置”，但不显示概览/期间费用总额。选择币种表示所有者确认这些记录使用同一币种，不会转换金额。设置页明确说明。使用币种选择器支持的大写三字母代码，拒绝未知输入。不得将多币种历史当作已换算后聚合。

缺少费用表示未知，不表示免费。仅累计已有费用并注明覆盖；明确零费用属于已知费用。不做费用编辑或汇率服务。

### 地点与最近记录值

优先显示非空 geofence 名称，否则使用地址名或道路/门牌号结合城市，否则显示“未知地点”。不进行外部逆地理编码，不默认用坐标作为列表地点名。

电量与所选续航分别从车辆 positions 和通过 charging_processes 关联的 charges 中选取最新有效值。里程表来自最新有效 position。同来源时间相同时按 ID 排序；两个来源时间相同时优先充电值。保留每项时间戳，不虚构共同快照时刻。不据此推断状态。页面进入及显式刷新时读取，不新增持续轮询。

### 曲线

返回命名序列、明确单位、UTC 时间边界、原始样本数、桶数和聚合元数据。每个序列最多 600 个时间桶。少量记录保留原始时间戳，较长记录使用等宽时间桶。连续量提供均值/最小值/最大值；SOC 提供最后有效值。图表展示均值/最后值，并在数据说明中解释范围/聚合。

空桶、缺失样本和超过五分钟的间隔必须断线。如果聚合会隐藏桶内缺测区间，标记该桶为不连续，不画穿过它的连接线。保留负功率，不跨 null 插值。字段缺失只影响该序列。聚合在 SQL 中完成，不向 Python/浏览器传递无限样本。未结束记录使用现有样本边界，不虚构完成时间。

现有路线采样独立处理，最多 2,000 点，保留简化及缺口标记。图表使用保存的时区，为鼠标、触摸和键盘用户提供可访问的文字说明。

### 只读访问与兼容

保留 M0 基础检查。新增能力独立诊断，使旧最小权限角色仍可使用已有列表字段、基本详情和地图。新增字段缺失时返回 null 加能力信息，或局部不可用区域；不得阻断认证、设置或恢复。

除 M0 列外，新增 SELECT 白名单限于下表。ID/外键仅用于所述关联。使用可选列前检查类型和有效列权限；不得先执行无权查询，再将失败解释为空数据。

| 表 | 新增列 |
| --- | --- |
| `cars` | `efficiency` |
| `drives` | `start_position_id`, `end_position_id`, `start_address_id`, `end_address_id`, `start_geofence_id`, `end_geofence_id`, `start_rated_range_km`, `end_rated_range_km`, `start_ideal_range_km`, `end_ideal_range_km` |
| `charging_processes` | `address_id`, `geofence_id`, `start_battery_level`, `end_battery_level`, `charge_energy_used`, `cost` |
| `positions` | `car_id`, `odometer`, `battery_level`, `rated_battery_range_km`, `ideal_battery_range_km`, `speed`, `power`, `inside_temp`, `outside_temp`, `elevation` |
| `charges` | `id`, `charging_process_id`, `date`, `battery_level`, `rated_battery_range_km`, `ideal_battery_range_km`, `charger_power`, `outside_temp` |
| `addresses` | `id`, `name`, `road`, `house_number`, `city` |
| `geofences` | `id`, `name` |

不读取 tokens、users、VIN 或无关设置。保留既有不安全角色拒绝机制。SQL 显式选择列，不使用 `SELECT *`。值必须参数化，动态选择的续航列名必须白名单化。

为显式指定的既有角色提供独立、幂等的升级脚本：仅授予必要 SELECT 列，不创建角色、不重置密码、不撤销无关授权。同步更新新角色准备流程，使其具有相同必要能力。应用不执行任何一个脚本。两种路径仅在合成 PostgreSQL 验证。

续航/币种偏好保存在现有 MateScope 配置中，旧 JSON 使用默认值。旧偏好更新若省略新字段，保留已有新值；显式 null 清空币种。不得仅为 JSON 偏好增加 SQLite schema 迁移。旧应用版本可能拒绝新增配置字段，因此即使没有 schema 迁移，回滚也可能需要恢复升级前备份。

### 合成隔离与规模

- 创建新的唯一 Compose 项目、独立卷/网络及明确选择的空闲回环端口。不得推断之前测试资源仍运行。

- 本地提供确定性地图瓦片，阻止无关浏览器请求。既有 MQTT/SMTP 回归仅使用新项目的测试服务。
- 不复用真实保存的连接设置。清理前登记归属资源，只删除本项目资源，绝不全局 prune。

### 响应式与浏览器验收

覆盖 360px、390px、768px、1280px、1440px；英中；浅色/深色；键盘日期/导航/记录访问；可访问图表说明；触摸目标和底部安全区。主页面不得横向滚动，长地点名不得挤走关键信息。

### 升级与回滚

1. 升级前备份 MateScope 自有数据，记录旧镜像。
2. 新版本使用既有账号启动；没有扩展授权时基础功能仍可用。
3. 单独授权的部署步骤中，由所有者检查/执行最小只读授权。
4. 显式重新测试数据源，验证新可用能力。
5. 检查选定车辆、日期、摘要和代表性详情。
6. 回滚时恢复旧镜像；若旧版本不能读取新配置，恢复升级前备份。不得假定无 SQLite 迁移就必然配置兼容。

保留当前恢复语义：会话和恢复码按已有规则失效，已启用验证器仍启用，`reset-password` 保留 2FA，`reset-2fa` 仍是显式运维恢复操作。不能因恢复后账号认证仍存在，就把已失效恢复码描述为保留。

任何步骤均不自动改生产服务、授予真实权限、发布镜像或执行实际回滚。人工走查必须使用合成或单独授权的目标，预期结果对应验收表。
